# CLAUDE.md — sdk-node

Repo guide for any agent working in `tracore-io/sdk-node`. Read before changing anything.

## Purpose

`@tracore/sdk` — the official TypeScript SDK for the Tracore API. It is **generated from the Tracore OpenAPI spec**, which is the single source of truth: the SDK never hand-describes request/response types or endpoints, so it cannot contradict the API. A hand-written ergonomic layer wraps the generated client with idiomatic resource groups, helpers, and typed errors.

## Layout

```
src/
├── generated/      # GENERATED — never edit by hand (carries a DO NOT EDIT header)
├── client.ts       # hand-written: TracoreClient (interceptors, extract convenience)
├── resources/      # hand-written: resource groups (workspaces, schemas, documents, runs, webhooks, environments, user, user-provider-keys)
├── helpers/        # hand-written: polling, error normalization
├── version.ts      # GENERATED const: the API contract version (regenerated by sync.yml)
├── types.ts        # re-exported generated API types
└── index.ts        # public entry: TracoreClient, resources, API_VERSION, types
openapi.yaml        # downloaded from the release asset; gitignored, never committed
.api-version        # the api-vX.Y.Z this repo is generated from (bare semver)
```

- **Never edit `src/generated/`.** It is owned by codegen; changes belong in the spec (monorepo) or the hand-written layer.
- **Never hand-edit `.claude/skills/polish-sdk-pr/SKILL.md`.** It is synced read-only from the canonical copy in the monorepo (`tooling/sdk-skills/polish-sdk-pr/SKILL.md`) by `sync-sdk-skill.yml`. Edit the canonical copy there.

## Regen flow

The spec ships as a versioned GitHub Release asset; an API release flows here automatically:

1. A maintainer cuts an `api-vX.Y.Z` tag in the monorepo; its release workflow publishes the spec to the public spec repo and fires a `repository_dispatch` `api-released` here.
2. `.github/workflows/sync.yml` (on that dispatch): pins `.api-version` + regenerates `src/version.ts`, downloads `openapi.yaml` from the release `spec_url` (sha256-verified when a sidecar exists), `pnpm generate`, writes a default version bump, refreshes the README "Built against" line, and opens a **draft** PR labeled `needs-polish`.
3. A maintainer runs the **`polish-sdk-pr`** skill locally (examples, helpers, README, CHANGELOG, migration guide if breaking, confirm the bump) — it flips the PR to `ready-for-review`. It never merges.
4. A human reviews and merges. Regeneration off-cycle (without waiting for a dispatch) is the **`sync-spec`** skill.

Never auto-merge a regen PR. Never edit generated output inside one.

## Versioning & compatibility

Two distinct version axes — do not conflate them:

- **API contract version** — which `api-vX.Y.Z` contract the SDK was generated from. Lives in three places kept **in lockstep** by `sync.yml`: `.api-version`, `src/version.ts` (`API_VERSION`), and `package.json#tracoreApiVersion`. The SDK sends it on every request as the `Tracore-Version` header and exposes it as `client.apiVersion` (and the exported `API_VERSION` const).
- **SDK package version** — `package.json#version`, the npm SemVer the consumer installs. This is the consumer contract: patch/minor are backward-compatible, **major = breaking**. A breaking API change forces a major SDK bump; while the SDK is pre-1.0 (`0.x`), "breaking" maps to a **minor** bump (the 0.x breaking lever). Helper/bugfix changes bump minor/patch independently of the API.

## Commands

```bash
pnpm install      # standalone install (no monorepo workspace)
pnpm generate     # regenerate src/generated/ from openapi.yaml (openapi-ts)
pnpm build        # tsup -> dist (ESM + CJS + d.ts)
pnpm typecheck    # tsc --noEmit
pnpm lint         # oxlint . && eslint
```

## Publish

Publishing is a deliberate, human-triggered act and uses npm **provenance** (which requires CI/OIDC — it cannot be produced from a laptop). Use the **`release-sdk`** skill to cut a release.

> **Publishing is NOT wired yet.** The publish workflow (`.github/workflows/publish.yml`, `workflow_dispatch` + `id-token: write` for provenance), the `@tracore` npm org, and the `NPM_TOKEN` secret are a separate, deferred "enable publishing" task. The `release-sdk` skill documents the intended flow but flags this prerequisite — do not assume you can publish today.

## Conventions

- TypeScript strict: never `any` (use `unknown` + narrowing). kebab-case file names.
- No emojis anywhere — code, comments, docs, commit messages.
- Keep diffs focused; no drive-by refactors of the generated or ergonomic layers.
